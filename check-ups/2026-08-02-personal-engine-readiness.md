# TrueTest — Personal Engine Readiness

**Scope**: Backtest + Research (+ optional shadow). **Excluded**: live tests / Phase-0 soaks.

## Summary

TrueTest ist für den persönlichen Alltag schon stark nutzbar: engine_backtest läuft mit lokalem CSV/synthetic, --seed und JSON-Report; Backend/UI-Jobschleife und einfache MC-Kampagnen funktionieren heute. Noch nicht „set-and-forget“-reif sind Job-Persistenz über Restarts, MC-Realismus/Reuse-Korrektheit, systematische OOS/Grids und ehrliches Shadow nur mit Trade+L2 — Live-Kapitaltests bleiben bewusst ausgelagert.

## Ready now

- CLI-Backtest: core/build/engine_backtest mit --provider local|synthetic, --seed, --output JSON
- Default-Serie data/market/binance_btcusdt_1m_2020-01-01_2023-04-04.csv + Fixtures/Golden sma_basic
- Fee/MM-Realismus-Flags (--fee, --mm-*, --realistic-fills) für Bar-Backtests
- Research-Loop: POST/GET /api/jobs, Report auf /jobs/:id, Cancel, Results-Liste
- MC-Basis: --monte-carlo --mc-trials GBM, deterministische Trial-Seeds, mc_aggregate_v1 + plot.py
- Strategy-Registry + --param für Built-ins (sma, mean-reversion, …) ohne UI-Authoring
- Shadow-CLI (attended): engine_shadow + ENABLE_BINANCE, TradeTapeShadowAdapter ohne Order-Send

## Not ready / gaps

- Job-Index nur in-memory Map — Restart verliert list/detail/report-by-id (Artifacts bleiben auf Disk)
- Kein First-Class Download/Log-Endpoint oder UI-Download-Button
- /reports ist Mock; echte Pfade sind /results und /jobs/:id
- MC: order_latency/impact_k in Campaign no-ops; keep_full_reports hohl; nur GBM; L2 ungenutzt auf Bar-Pfad
- IStrategy::reset unvollständig (sma/breakout/adaptive) → Leak unter --mc-reuse-objects
- Kein Walk-Forward/OOS-Windowing und kein Param-Grid-Runner (nur manuelle Jobs)
- Multi-Symbol-Portfolio-Research / Account-Level-Risk (R-04) nicht first-class
- Parquet/HTTP-History deferred — nur CSV/synthetic/binary-replay ohne Eigenkonvertierung
- Bar-only Shadow lehrt optimistische Mikrostruktur; multi-session Shadow-Compare-Tooling unvollständig

## Milestones (do in order)

### 1. Tägliche CLI-Backtests stabilisieren

**Goal:** Jeden Tag reproduzierbare Single-Symbol-Backtests mit fester Binary, Seed und JSON-Artefakt — ohne UI.

**Done when:** Zwei Läufe mit identischen Flags liefern dieselben Key-Metrics im --output JSON; golden/cli-Tests grün; smoke JSON existiert und parsebar.

Actions:
- cd core && cmake --preset linux-tests && cmake --build --preset linux-tests -j --target engine_backtest truetest_tests
- ctest --test-dir build -R 'golden|cli' --output-on-failure (test_golden_regression + test_cli)
- Smoke: ./build/engine_backtest --provider synthetic --mc-params 'mu=0,sigma=0.02,n_steps=500,initial_price=100' --strategy sma --seed 424242 --no-pin --status-format off --no-tui --output /tmp/smoke_bt.json
- CSV-Smoke auf kurzem Slice: --provider local --path tests/fixtures/sample_ohlcv.csv --strategy sma --seed 1 --fee fixed --fee-value 0 --output /tmp/csv_bt.json
- Operator-Notiz: gleiche CORE_BINARY, --seed, Strategy/--param und Report-Hash/Metrics speichern; Full 1.7M-CSV nur wenn Zeitbudget da

### 2. Research-Job-Loop multi-session tauglich

**Goal:** UI→Backend→engine_backtest über Prozess-Restarts und Export hinweg nutzbar halten.

**Done when:** Nach Backend-Restart erscheinen completed Jobs inkl. report-by-id; Download liefert denselben JSON wie core --output; Cancel pending/running funktioniert weiter.

Actions:
- export CORE_BINARY=../core/build/engine_backtest ARTIFACTS_DIR=./artifacts DATA_ROOT=..; cd backend && npm run dev
- cd UI && NEXT_PUBLIC_BACKEND_URL=http://localhost:3001 npm run dev; Job von /backtester mit provider=local oder synthetic submitten
- Implement: Job-Index rehydrate aus ARTIFACTS_DIR (*.meta.json / jobs.jsonl) in backend/src/job-service.ts + start in index.ts (Phase-3 Storage laut FUNDAMENTAL-ARCHITECTURE.md)
- Implement: GET /api/jobs/:id/report mit Content-Disposition attachment + optional GET .../log; UI Download auf jobs/[id]/page.tsx
- Verify: Job laufen, Backend restart, GET /api/jobs und /api/jobs/:id/report liefern denselben completed Job; curl speichert report.json

### 3. MC-Robustheit für Path-Noise-Studien

**Goal:** Persönliche GBM-Kampagnen korrekt und interpretierbar (Verteilungen, nicht Fill-Mikrostruktur).

**Done when:** 50-Trial-GBM mit festem Seed reproduzierbar; mean-reversion (und mindestens sma) unter --mc-reuse-objects ohne State-Leak; JSON trials[]+aggregate parsebar; Operator kennt L2/realism-Grenzen.

- python3 core/scripts/plot.py /tmp/mc.json (oder Äquivalent) — PnL/Sharpe/DD-Verteilungen prüfen
- Fix MC-05: reset() in sma_strategy, ma-crossover, breakout, adaptive_hybrid; Test mit --mc-reuse-objects vs fresh objects gleiche Aggregate (Toleranz)
- Dokumentieren in docs/reference/02-user-manual.md: latency/impact CLI sind Campaign-No-Ops bis verdrahtet; nur Path-Noise-Claims
- Optional days: MonteCarloController engine_config um order_latency_us/impact_k_bps verdrahten ODER Flags in MC-Mode ablehnen

### 4. Daten-Ergonomie (CSV-first)

**Goal:** Schnelle Iteration auf lokalen CSV-Slices; Parquet/API nur als optionaler Convert-Pfad.

**Done when:** Operator kann in <2 min interaktiv einen Job auf kurzem CSV beenden; Full-History-Lauf bleibt optional; kein Dependency-Approval nötig für den Standardpfad.

Actions:
- Kurze Research-Slices unter data/market/ (z.B. 3–6 Monate) erzeugen und in UI SEED_SOURCES / backend DATA_ROOT referenzieren
- Optional hours: DataLoadOptions from/to/symbols in DataWrapper::load anwenden (data_wrapper.cpp) für IS/OOS ohne externes Schneiden
- CLI-Dokument: core/docs/internal/data-pipeline.md CSV-Schemas (OHLCV open/high/low/close; tick ts_ms,symbol,price,qty) als Convert-Ziel für fremde Formate
- Nicht blockieren auf D-08/D-09 — bei Bedarf offline Parquet→CSV; backend bleibt local|synthetic

### 5. Strategie-Research-Handlauf

**Goal:** Neue Bar-Strategien und manuelle Param-Sweeps ohne Fake-UI-Claims.

**Done when:** Mindestens eine neue oder getunte Strategie läuft CLI+Job mit --param; MC-reuse-safe reset wo genutzt; keine UI-Route behauptet Grid/WF das Core nicht kann.

Actions:
- Template: IStrategy + REGISTER_STRATEGY + cmake/Sources.cmake + rebuild; golden analog tests/golden/sma_basic_*
- ExperimentForm: strategy params UI verdrahten (Backend core-runner.ts mappt params→--param bereits)
- Manueller Grid: Shell/Script fächer --param Kombinationen mit festem --seed-Policy und sammelt --output JSONs
- UI strategy-lab /reports als Mock belassen oder Nav auf /results+/jobs/:id umbiegen — keine Walk-Forward-Claims

### 6. Optional: Shadow-Lernen (attended CLI)

**Goal:** Paper/Divergence-Lernen ohne Orders — nur wenn Trade+Depth-Pfad genutzt wird.

**Done when:** Eine attended Session startet, sendet keine Orders, liefert sim-vs-tape Divergence-Output; Operator dokumentiert Fidelity-Grenzen (Funding R-03, single-venue Binance golden).

Actions:
- cmake -B build -DENABLE_BINANCE=ON && cmake --build build -j --target engine_shadow
- Session: ./build/engine_shadow --provider binance-futures --symbol BTCUSDT --stream trade --depth-stream depth20@100ms --strategy mean-reversion --queue-model l2-snapshot (kein bar/kline-only Learning)
- ShadowTracker-Report speichern; User-Manual-Beispiel von kline-only auf trade+depth angleichen (docs/reference/02-user-manual.md)
- Kein Backend/UI-Shadow-Job erwarten (FUNDAMENTAL-ARCHITECTURE: backtest-only launcher)

## Deferred (live / capital — not this roadmap)

- Phase-0 Live-Sessions und Operator-Ritual (docs/governance/01-prod.md)
- Mainnet soaks / capital gates / live size increases
- engine_live + interactive captcha + API credentials path
- LIVE_SAFETY_CCB_APPROVED Freeze-Änderungen (kill/DMS/reconciler/halt)
- QuestDB production soak / dual-portfolio live persistence requirements
- Multi-venue live/paper productization (Bitunix missing, Bybit/Gate archived)

## Risks

- Bar-OHLCV-Kosten kommen aus MM-Kalibrierung, nicht realem L2 — Mikrostruktur-Claims leicht überzogen
- MC misinterpretiert als Fill-Realismus-Studie obwohl latency/impact Campaign-No-Ops und L2 ungenutzt
- --mc-reuse-objects mit Strategien ohne reset() verfälscht Trial-Verteilungen
- Backend-Restart ohne Storage-Upgrade → „verlorene“ Jobs trotz vorhandener Artifact-Dateien
- Full 1.7M-Bar-CSV macht UI-Iteration multi-minute und wirkt wie „hängt“
- Shadow auf kline/bar-only lehrt fake Fills; nur trade+depth ist lehrreich
- Multi-Symbol-CSV-Load ≠ wissenschaftliches Portfolio-Risk (R-04 / single last_mid_price_)
