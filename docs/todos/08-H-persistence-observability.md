# H: Persistence, Observability & Hardening (later phases)

**See**: docs/todos/00-OVERVIEW.md for full rules, reference format, maintenance, and mapping. High-level also in thin `docs/governance/03-todo.md`. All QuestDB / persistence work happens on the `database` branch.

Primary reference: `docs/reference/03-db.md` (current authoritative schema + queries + reliability + ritual) and `docs/archive/questdb-multi-week-hardening-guide.md` (historical phased log; most phases landed).

- **H-01** Strict mode is fail-closed for normal engine runs: startup/runtime failure returns non-zero, and shadow/live additionally halt. Soft `--persist` still warns and continues. Monte Carlo deliberately rejects `--persist-strict` until its summary writer can propagate failures. Automatic retry is not part of the strict contract; any first write failure latches failure. Local fallback is diagnostic only.
- **H-02** Make structured binary event logging + integrity verification mandatory in live mode.
- **H-03** Implement reliable crash recovery (position + open-order replay from binary logs). (Richer checkpoints; crash-replay golden tests.)
- **H-04** Add Prometheus / metrics export endpoint + structured alerting hooks (halt, large loss, DMS trigger, etc.). (IAlertSink; alerting drill — Go-Live row 6.)
- **H-05** Encrypted credential store + key rotation support. (Demonstrated on ≥10 sessions — Go-Live row 5.)
- **H-06** Automatic tape rotation + offsite / cloud backup helpers.
- **H-07 — OPEN; FROZEN-SURFACE TRACK (found 2026-08-18, `/update-docs` audit)** The mainnet Phase 0 gate (`src/bin/main.inc:526-532`, `!sandbox && o.event_log_path.empty()`) only checks that `--log-events` was *set*, never that its target is a regular, recoverable file. `EventLogger`/`EventLogWriter::ensure_open()` (`src/core/event_log.h:940-1037`) opens the path via plain `std::ofstream out_.open(path_, ...)`, which succeeds silently against `/dev/null`, a FIFO, a device node, or a symlink to one of those — every write "succeeds" while the durable ledger is actually discarded. This directly undermines the guarantee `docs/governance/01-prod.md` and the operator SOP state as mandatory ("`--log-events`: binary zstd event log is the mandatory durable truth") and is the same gap the trading-logic-audit decision record (`docs/internal/trading-logic-audit-2026-08-17.md`, "Residual risks" section) already flagged as unresolved.
  - **Target design**: validate `o.event_log_path` at CLI/mainnet-gate time (and defensively again in `ensure_open()`/`EventLogger` construction) — reject non-regular-file targets (`std::filesystem::is_regular_file` on an existing path; for a not-yet-existing path, verify the parent directory exists and is writable, then re-check `is_regular_file` immediately after the first open) before any run starts. Mainnet (`!sandbox`) should refuse to start rather than warn; sandbox/backtest/shadow can keep the existing softer posture but should still surface a warning so a silently discarding `/dev/null` sink isn't mistaken for a working log in shadow soak runs either.
  - **Frozen scope**: `src/bin/main.inc` (mainnet gate check) is Phase 1 frozen — this needs the `LIVE_SAFETY_CCB_APPROVED` token, human T3 ADR/CCB approval, and a clean multi-hour `engine_shadow` run per `docs/todos/02-P1-freeze.md` P1-05 before merge, same as the BF-* frozen track (`docs/todos/10-BF-backtest-engine-bugfixes.md`). `src/core/event_log.h` is **not** on the frozen list (`scripts/check-live-safety-freeze.sh`) and can be hardened independently/first as a non-frozen defense-in-depth PR — do that before touching `main.inc` so the frozen diff stays minimal (same pattern BF-13 used for `engine.cpp`).
  - **Tests before implementation**: reject `/dev/null` and a FIFO (`mkfifo`) at mainnet startup with a clear error, before any engine construction; accept a normal regular-file path (existing and not-yet-existing, including a fresh subdirectory) on mainnet; sandbox/backtest/shadow still start against `/dev/null` but emit a visible warning; a symlink to `/dev/null` is treated the same as `/dev/null` itself.
  - **Status (2026-08-18)**: implemented in the working tree (non-frozen `event_log.h` helper `is_acceptable_durable_log_target()` + frozen `main.inc` call site in `validate_binance_futures_live_phase0`), with the full test set from "Tests before implementation" above, plus 4 more a fresh independent review surfaced (empty-path, missing-parent-directory, symlink-to-`/dev/null`, symlink-loop fail-closed) after that review caught two real bugs in the first pass (an unchecked `std::error_code` on `exists()`'s failure path, and an empty string returning `true`) — both fixed. **Not committed.** No CCB review has happened; nobody has typed `LIVE_SAFETY_CCB_APPROVED` into a commit for this diff and none should until an actual second reviewer has looked at it. The `event_log.h` half is not frozen and could land independently.
  - **New residual gap found during that review (not fixed by this patch, needs its own item)**: `validate_binance_futures_live_phase0` — venue-caps requirement, daily-loss requirement, the durable-log-empty check, the new durable-log-target check (this item), and the rotation check — all early-return `true` (skip entirely) at `src/bin/main.inc:491` unless `is_futures_live_provider(o.provider_name)` is true. Plain spot `--provider binance --mode live --live` is **not** a futures live provider by that predicate, so a real spot-Binance mainnet live run currently gets none of these Phase-0 safeguards, only the finite-value sanity checks that run earlier in the same function. This is broader than H-07 (it is every check in that function, not just the durable-log target) and predates this session's patch — it is not introduced by H-07, only discovered while scoping it. Needs its own todo item and its own CCB track once someone decides whether spot Binance live is meant to be Phase-0-gated the same way futures is.
