# H: Persistence, Observability & Hardening (later phases)

**See**: docs/todos/00-OVERVIEW.md for full rules, reference format, maintenance, and mapping. High-level also in thin `docs/governance/03-todo.md`. All QuestDB / persistence work happens on the `database` branch.

Primary reference: `docs/reference/03-db.md` (current authoritative schema + queries + reliability + ritual) and `docs/archive/questdb-multi-week-hardening-guide.md` (historical phased log; most phases landed).

- **H-01** Strict mode is fail-closed for normal engine runs: startup/runtime failure returns non-zero, and shadow/live additionally halt. Soft `--persist` still warns and continues. Monte Carlo deliberately rejects `--persist-strict` until its summary writer can propagate failures. Automatic retry is not part of the strict contract; any first write failure latches failure. Local fallback is diagnostic only.
- **H-02 — PARTIAL** Mainnet live now requires a binary event log in the
  current worktree, subject to H-07 governance/evidence. Path/inode/link
  verification and clean-finalized replay eligibility are implemented; a
  cryptographic hash/signature integrity chain is not.
- **H-03** Implement reliable crash recovery (position + open-order replay from
  binary logs) and the missing complete command-WAL contract. That contract must
  define durable-before-command intent and authoritative outcome/reconciliation
  for cancel, amend, venue-native bracket operations, and kill-switch/DMS/native
  safety cancel-or-flatten commands, plus richer checkpoints, stable command
  identity, restart semantics, and crash-replay golden tests. The H-07
  order-intent ACK does not provide exactly-once execution or close this item.
- **H-04** Add Prometheus / metrics export endpoint + structured alerting hooks (halt, large loss, DMS trigger, etc.). (IAlertSink; alerting drill — Go-Live row 6.)
- **H-05** Encrypted credential store + key rotation support. (Demonstrated on ≥10 sessions — Go-Live row 5.)
- **H-06** Automatic tape rotation + offsite / cloud backup helpers.
- **H-08 — OPEN** Bound worker shutdown without unsafe detach/cancellation.
  Worker callbacks currently have no stop-token contract and durable logging
  performs synchronous filesystem flush/fsync; `std::thread::join()` has no
  deadline and a kernel-blocked callback is not portably cancellable. A sound
  fix requires cooperative cancellation plus bounded/cancellable I/O throughout
  every handler, or durable logging isolation in a supervised helper process.
  Detach, `pthread_cancel`, and timed-wait-then-destroy are rejected because
  workers retain engine/ring/pool state. This is an availability gap, not a
  false-seal path: the provider is shut down first and a logger that never joins
  cannot reach explicit terminal sealing.
- **H-07 — IMPLEMENTED IN CURRENT WORKTREE; GOVERNANCE/EVIDENCE OPEN (found 2026-08-18, frozen-surface track)** The original audit found that mainnet only checked whether `--log-events` was present and could silently accept `/dev/null`, FIFOs, devices, or symlink redirection. The current worktree replaces that design with atomic creation of a unique new regular file beneath an existing symlink-free parent, retained file/parent descriptors, ownership/link/inode checks, a one-time reservation claim before logger truncation, pre-provider preamble sync, path-identity rechecks, mainnet rotation refusal, and a required dedicated logging worker. Spot and futures mainnet both receive the daily-loss and durable-ledger gates; futures additionally require all three positive venue caps, DMS, unwind, and reconciliation tolerance in `(0,3]`. Bitunix `--demo`/`--testnet` flags are refused in every engine mode because no sandbox endpoint exists.
  - **Ownership/topology boundary**: the writable logger is a move-only capability outside copyable `engine_config` and transfers once from startup to engine to logging worker; a copied reservation cannot create another writer. Direct reserved sessions refuse `inline` and `light`. The durability SPSC channel exposes only a move-only producer to the logger and a move-only consumer to the engine. A single shutdown inventory checks exact expected worker/ring topology, every inbound backlog and drop counter, the MM outbound ring, ACK health/emptiness, and successful retirement of every never-submitted local scheduler entry before sealing. Scheduler retirement updates only local lifecycle state and never calls an adapter. Converted streaming `runtime_failure` is terminal, and a reusable `DataBridge` retains no engine halt pointer after the active call.
  - **Pre-submit order boundary**: normal and generic `risk_unwind` orders publish the exact order intent, then wait for the logging worker's matching order-ID ACK before adapter submission. The ACK follows the reserved logger's immediate flush, file/directory fsync, and identity recheck; both ACK production and engine consumption must occur before the fixed two-second deadline. A lock-free terminal gate then spans audit/setup and adapter mutation. Its CAS is the linearization point: a command admitted before concurrent `close()` is in flight, and no command is admitted afterward. Failure, mismatch, timeout, setup failure, post-ACK admission refusal, or a halt observed before admission sticky-compromises the ledger, halts, and refuses submission. The deadline bounds only the ACK wait; it cannot interrupt an earlier blocking publish to another worker ring, a blocked kernel `fsync`, provider shutdown, or the later worker join.
  - **Authority/finalization boundary**: fills, funding, rejections, and emitted cancel/amend records checkpoint when the logging worker consumes them; observational records checkpoint after 256 consumed records or when a later record observes at least 100 ms since completion of the prior sync. Finalization requires successful provider quiesce/kill/close, then drains the stable final tracked funding, synthetic metadata, submit-result, and fill queues before worker shutdown. A retained late fill uses teardown-only accounting that suppresses strategy, ExitManager, and position callbacks, so it cannot place/cancel a venue bracket after close. Failed/ambiguous provider shutdown, final-queue processing failure, uncertain outcomes, funding ingress loss, worker failure/backlog, drops, remaining ACKs, or any earlier sticky compromise refuses sealing. Reserved logger destruction never seals implicitly. V3 gives each record CRC32C and fsyncs the full index/trailer prefix first, then appends and separately fsyncs a terminal seal committing covered length, record count, index metadata, and the covered-prefix CRC32C. A complete valid seal is the crash-recovery authority even if the writer observed an uncertain final fsync result; operational evidence must additionally show both phases returned successfully. Writers lock before truncation and retain the old segment lock until a rotated successor is locked; sealed readers pin the inode, retain a shared advisory lock, and continuously recheck source metadata, so detected append/rewrite/path replacement revokes authority. Unknown venue-native bracket/kill outcomes remain explicitly outside H-07 under H-03. Worker backlog, an idle final observational record, and abrupt termination can therefore leave a diagnostic-only unsealed prefix.
  - **Explicit non-goals**: H-07 is not a full command WAL, exactly-once execution, crash recovery, or cryptographic tamper evidence. Durable-before-command intent/outcome coverage for cancel, amend, venue-native brackets, and kill-switch/DMS/native safety cancel-or-flatten commands plus state reconstruction remains H-03/follow-up. Mainnet reservation hardening does not apply to ordinary backtest, shadow, or sandbox paths.
